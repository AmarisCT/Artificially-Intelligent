Machine learning fundamentals

Machine learning replaces hand-written rules with a procedure that adjusts itself using data. This lesson explains the ingredients, and includes a working demonstration of why fitting data too closely can backfire.

Learning objectives

  • Name the main ingredients of a machine learning system.
  • Explain overfitting and why a test set is needed.
  • Describe supervised, unsupervised and reinforcement learning in one sentence each.

Learning from examples

A machine learning system has four ingredients: data, a model with adjustable settings called parameters, a measure of how wrong the model currently is, and a procedure that adjusts the parameters to reduce that error. The result is a model whose behaviour depends on the data it was trained on, not only on what its designers wrote.

In supervised learning the data come with the right answers, such as photographs labelled with what they show. In unsupervised learning there are no labels and the system looks for structure. In reinforcement learning a system acts, receives rewards or penalties, and learns which actions lead to better outcomes.

Fitting versus generalising

A model that matches its training data perfectly has not necessarily learned anything useful. It may have memorised noise. This is called overfitting. What matters is generalisation: performance on new data that the model has not seen. To check this, practitioners hold back some data as a test set and measure error there.

Why this matters beyond the demo

The same pattern appears in large systems. A system evaluated on data that overlaps with its training data can look better than it is. The quality of the data also limits the quality of the model: if the data leave out groups of people or situations, the model's behaviour there is unreliable.

A worked example: learning to recognise handwriting

Suppose you want a program to read handwritten digits. In a machine learning approach you collect many images of digits with their correct labels, choose a model with adjustable parameters, and train it to reduce its errors. Then you test it on digits it has not seen, including handwriting styles different from those in the training set. If it does well on the training digits and poorly on new ones, it has not generalised. If it fails on a style that was never in the data, the problem is the data's coverage, not only the model. This shows why the data and the test matter as much as the algorithm.

Common misunderstandings

  • “A model that fits the training data perfectly is a good model.” It may have fit noise. Performance on held-back data shows whether it generalises.
  • “More flexible models are always better.” Flexibility helps up to a point. Beyond it the model fits noise and generalises worse, as the demonstration shows.

Reflection question
